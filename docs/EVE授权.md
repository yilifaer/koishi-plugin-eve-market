# EVE 授权（联盟建筑市场）

联盟的玩家建筑（例如「联盟市场A」）里的订单，ESI 只给能停靠这个建筑的角色看。所以要用一个**能停靠的角色**（下面叫「服务角色」）授权一次，插件才能每隔几分钟把整个建筑市场的订单同步下来，群友查价时直接用。

只需要做一次。整个过程大约 10 分钟，分 5 步：

1. 在 EVE 开发者网站创建一个应用；
2. 把应用的 Client ID 和 Secret Key 填进 Koishi 控制台；
3. 打开授权页面，用服务角色授权；
4. 按名字找到建筑，填进控制台的「市场」表格；
5. 在 QQ（或者 Koishi 的沙盒）里发「市场状态」确认。

> 下文的「联盟市场A」「XX-1」「1000000000001」都是编造的例子，换成你们自己的建筑。
> 标着「待核实」的地方是 EVE 网站上的写法或行为还没有逐一确认，以你看到的为准；有出入请告诉开发者。
> 下文在 Koishi 控制台里说「保存」，都是指点配置页右上角的勾号图标「重载配置」（鼠标移上去会显示名字），或者按 Ctrl+S。配置页上没有写着「保存」两个字的按钮，详见 [控制台配置.md](控制台配置.md) 的「怎么保存」。

## 开始之前：「你打开控制台用的地址」

授权页面和 Koishi 控制台用的是**同一个地址**。下文说「你打开控制台用的地址」，就是你平时在浏览器地址栏里打开 Koishi 控制台的那一段：`http://` 开头，到端口号为止。

例如你经 SSH 隧道打开控制台，地址栏里是 `http://127.0.0.1:12345/`（12345 只是举例，下文都换成你自己地址栏里的端口），那么：

| 用途 | 地址 |
|---|---|
| 你打开控制台用的地址 | `http://127.0.0.1:12345` |
| EVE 授权页面 | `http://127.0.0.1:12345/eve-market/admin` |
| 回调地址（Callback URL） | `http://127.0.0.1:12345/eve-market/sso/callback` |

- 授权页面不用自己拼地址：控制台里本插件的设置页**最上面**有一个「打开 EVE 授权页面」，点它就行。
- 授权页面**只接受在 Koishi 所在电脑上直接打开**，地址要用 `127.0.0.1` 或 `localhost`；经 SSH 隧道打开也算本机。在别的电脑上打开、或者经反向代理、内网穿透转发过来，会显示「只接受本机访问」，这是正常的保护。
- 授权页面挂在 Koishi 的 server 插件上（Koishi 控制台本身也用它，一般都有）。没有时 QQ 里的「市场状态」会写「授权页面：需要 Koishi 的 server 插件」。

## 第 1 步：在 EVE 开发者网站创建应用

1. 用浏览器打开 `https://developers.eveonline.com`，点右上角的 **LOG IN**，用 EVE 账号登录。用哪个账号创建应用都可以，不一定是服务角色所在的账号（对账号有没有要求待核实）。
2. 进入 **Applications**（我的应用），点 **Create New Application**（创建应用）。
3. **Name**（名称）和 **Description**（描述）随便写，例如「联盟市场助手」「QQ 群查价用」。它们会显示在授权时的 EVE 登录页上，不用写联盟名。
4. **Connection Type**（连接类型）选带 API 访问的那一种，一般写作 **Authentication & API Access**（界面上的确切写法待核实）。
5. **Permissions**（权限）：在列表里找到并勾上下面三项（列表很长，可以用页面上的搜索框）：

   | 权限 | 用途 |
   |---|---|
   | `esi-markets.structure_markets.v1` | 读建筑市场的订单（必须） |
   | `esi-universe.read_structures.v1` | 读建筑的名字和所在星系（必须） |
   | `esi-search.search_structures.v1` | 授权页面里按名字找建筑（没有它也能同步，只是不能搜索） |

6. **Callback URL**（回调地址）：填「你打开控制台用的地址」后面接 `/eve-market/sso/callback`，例如：

   ```
   http://127.0.0.1:12345/eve-market/sso/callback
   ```

   最稳妥的办法：先在控制台点「打开 EVE 授权页面」，页面「第 1 步」那一栏显示的就是应该填的这一行，旁边有「复制」按钮，**照抄**。

   - 必须和控制台里的「回调地址」**一模一样**：`http` 和 `https`、`127.0.0.1` 和 `localhost`、端口号、末尾有没有 `/`，任何一点不同 EVE 都会拒绝。
   - `http://127.0.0.1` 开头的地址 EVE 是接受的（已实测）。
7. 同意条款，点创建。

## 第 2 步：把应用信息填进 Koishi 控制台

1. 在开发者网站的应用列表里点开刚才的应用（**View Application**），找到 **Client ID** 和 **Secret Key**。
2. **Secret Key 当作密码对待**（能不能以后再看待核实，按「只显示一次」准备）：存进密码管理器，或者本机一个不同步到网盘的文本文件；**不要截图，不要发到任何聊天里**。泄露了就在开发者网站上重新生成，再把新的填回控制台、重新授权一次。
3. 打开 Koishi 控制台 → 插件配置 → 本插件（eve-market）→ 往下找到 **EVE 授权** 这一组：

   | 配置项 | 填什么 |
   |---|---|
   | Client ID | 粘贴应用的 Client ID |
   | Secret Key | 粘贴应用的 Secret Key（只填在这里） |
   | 回调地址 | 和开发者网站上的 Callback URL **一模一样**，例如 `http://127.0.0.1:12345/eve-market/sso/callback` |
   | 授权页面的口令 | 只要这台电脑上有**反向代理**（例如 QQ 机器人用 webhook 方式时的 nginx、Caddy）、**内网穿透**（frp、花生壳、cloudflared 之类）或端口转发把 Koishi 的端口开放出去，就**一定要设**一个；这些都没有时可以不填 |

   回调地址的默认值 `http://127.0.0.1:5140/eve-market/sso/callback` 只适合「就在 Koishi 那台电脑上、用 5140 端口打开控制台」的情况；经隧道换了端口的，一定要改。

   为什么开放了端口就要设口令：反向代理、内网穿透转发过来的访问，在 Koishi 看来也来自本机。插件会拒绝带着转发标记的访问，但不是所有转发工具都会加这个标记，口令是最后一道保护。

4. 保存：点右上角的勾号图标「重载配置」，或者按 Ctrl+S。改了内容时插件会重载一次（几秒钟），不影响别的插件。

## 第 3 步：用服务角色授权

1. 在控制台本插件设置页的最上面，点 **打开 EVE 授权页面**。
2. 看页面的「第 1 步」：
   - 显示绿色的「和控制台里填的回调地址一致」：好。
   - 显示红框：控制台里的回调地址和你现在用的地址不一样，按红框里的提示改好、保存，再刷新授权页面。
   - Client ID、Secret Key 显示「没填」：回到第 2 步。
3. 在「第 2 步：授权角色」的表格里，`default` 那一行点 **授权**。表格里还没有任何档案时，下面有一个「新档案名」输入框，保留 `default`，点 **授权**。
4. 浏览器会跳到 EVE 的登录页：
   - **浏览器里已经登录的 EVE 账号会被直接用上**。如果不是服务角色所在的账号，先在登录页上退出，再用正确的账号登录。
   - 在角色列表里选**能停靠联盟建筑的那个角色**。
   - 看一眼要授权的权限（就是第 1 步勾的三项），点同意（**Authorize**）。
5. 浏览器回到「**授权成功**」页面：写着「档案 default 已经授权给角色『…』」，下面列出每个用这个档案的建筑市场能不能访问：

   | 结果 | 意思 | 怎么办 |
   |---|---|---|
   | 可以访问 | 正常 | 不用管 |
   | 没有权限（403） | 这个角色不能停靠这个建筑，或者建筑没有对它开放市场 | 换一个能停靠的角色重新授权，或者请建筑管理者把这个角色加进访问名单 |
   | 找不到 | 「市场」表格里的建筑 ID 不对 | 用第 4 步重新查 ID |
   | 暂时查不到，稍后在 QQ 里发「市场状态」看看 | 这一下没连上 EVE（网络或 EVE 那边的问题），不是授权的问题 | 过几分钟在 QQ 里发「市场状态」，看这个建筑市场是不是 🟢 |

   还没往「市场」表格里加建筑时，这里是空的，接着做第 4 步。

授权以后，插件把 EVE 给的刷新令牌**加密**保存在本机数据库里（密钥是单独的文件 `secret.key`，见后面的「换电脑」）。授权页面、QQ 消息和日志里都不会显示任何令牌或 Secret Key。

## 第 4 步：找到建筑，填进「市场」表格

1. 回到授权页面（授权成功页最下面有「返回授权页面」），找到「**第 3 步：按名字找建筑**」。
2. 「用档案」选 `default`，「建筑名」输入建筑名字的一部分（至少 3 个字），点 **搜索**。只能搜到这个角色能看到的建筑。
3. 结果每一行是建筑的**名称、星系、建筑 ID**（ID 旁边有「复制」按钮），下面一行写明「市场」表格该怎么填。
   - 名称显示「（看不到名字）」的：这个角色搜得到这个建筑，但看不到详情，多半不能停靠，加进表格以后同步会被拒绝（403）。要用它，就换一个能停靠它的角色授权以后再搜。
   - 那一行写着「建筑所在星系留空」时，表格里这一格就空着，插件授权后会自己查。
4. 打开控制台本插件的「**市场**」表格，点表格标题右边的「添加行」，在新的一行（最下面）里填：

   | 列 | 填什么 | 例子 |
   |---|---|---|
   | 名称 | 群友查价时打的名字，表格里不能重复 | `联盟市场A` |
   | 别名 | 可选，多个用逗号分隔 | `市场A, A市` |
   | 类型 | 玩家建筑 | |
   | 位置 | 建筑 ID（照抄搜索结果） | `1000000000001` |
   | 建筑所在星系 | 可以留空（授权后插件自己查）；填上更好 | `XX-1` |
   | 默认查价 | 自动（玩家建筑会列在「查价 物品」里） | |
   | 谁能看到 | 自动（玩家建筑只在授权群显示） | |
   | 授权档案 | `default` | |

5. 保存。插件重载以后半分钟内开始第一次同步，以后大约每 5 分钟一次（按 ESI 给的缓存时间）；24 小时没人查会暂停，有人查时自动恢复。

搜索用不了的时候，也可以在游戏里把建筑拖进聊天框，复制出来的文字里 `showinfo:类型ID//建筑ID` 的第二个数字就是建筑 ID（复制出来的格式待实测）。

## 第 5 步：确认

在 QQ 里用**管理员**身份（控制台「权限 → 管理员」里填的 ID）私聊机器人，或者在授权群里 @机器人，发：

```
市场状态
```

正常时能看到这样两行：

```
- 联盟市场A：🟢 正常 · 建筑市场 · 同步于 14:16 · 3 页 2,841 单
- 授权档案 default：🟢 令牌有效 · 权限 3/3 · 刷新于 14:01
```

再在授权群里发「查价 乌鸦级」，应该能看到「联盟市场A」的价格。在没有授权的群里看不到这个市场，这是正常的（联盟价格只给授权群看）。

发「**市场授权**」可以只看授权档案：角色、权限、上次刷新、用到它的市场。

「市场状态」「市场授权」只回应管理员，并且只在私聊或授权群里回应；别人发了没有任何反应，帮助里也看不到这两个命令。消息里只有状态，不会出现口令和网址。

**QQ 机器人还没接好时，可以先在 Koishi 的沙盒里确认**：

1. 控制台本插件设置的「基本」里，打开 `allowSandbox`（说明写着「测试用：也在 Koishi 控制台的「沙盒」里回复」），保存。
2. 打开 Koishi 控制台左边的「沙盒」：点「添加用户」，选中出现的用户，再点上方的「私聊模式」（详见 [测试步骤.md](测试步骤.md) 的「A 的准备」）。发 `本群ID`，记下回复里你自己的 ID。
3. 在控制台「权限」里点「管理员」（`admins`）右边的「添加项目」，粘贴这个 ID，保存。
4. 回到沙盒私聊发 `市场状态`，看到上面那样的两行就对了。
5. 测完把 `allowSandbox` 关掉，「管理员」里沙盒的那个 ID 也可以删掉。

## 「市场状态」里的状态

建筑市场：

| 显示 | 意思 | 群友查价时看到 |
|---|---|---|
| 🟢 正常 | 同步正常，后面写着上次同步的时间和订单数 | 价格 |
| ⏳ 首次同步中 | 刚加进表格或刚授权，第一次同步还没完成 | 「首次同步中，请稍后再查」 |
| 🟡 需要授权 | 档案还没授权，或者控制台没填 Client ID | 「市场数据暂时不可用（ESI 授权或建筑访问权限异常）」 |
| 🟡 同步异常 | ESI 暂时出错，会自动重试 | 60 分钟以内的旧价格（标着时间），更久就是「暂时不可用」 |
| 🔴 授权异常 | 403（角色失去停靠或市场访问权限）、令牌被拒，或者档案需要重新授权 | 「市场数据暂时不可用（ESI 授权或建筑访问权限异常）」 |

授权异常时**不显示旧价格**；同一条查价回复里的其他市场（Jita 等）照常显示。

授权档案：

| 显示 | 意思 |
|---|---|
| 🟢 令牌有效 / 🟢 正常 | 正常 |
| 🟡 需要授权 | 还没授权；或者密钥变了（见「换电脑」），下面一行写着原因 |
| 🟡 暂时刷新不了 | 连不上 EVE 登录服务器，会自动重试（1、5、15、60 分钟），不用管 |
| 🔴 需要重新授权 | 刷新令牌失效（被撤销或过期）、角色转手、权限不够、EVE 不认这个应用的 Client ID 或 Secret Key。下面一行写着原因，按「重新授权」做 |

`市场状态 刷新`（或点卡片上的「立即刷新」）：马上检查一次在线数据，并且**只**重新同步已经过期或出错的建筑市场；还没过期的不会重新请求（这是 ESI 的使用规则）。

## 重新授权

什么时候要做：「市场状态」里档案显示「🔴 需要重新授权」，或者显示「🟡 需要授权」并写着「密钥变了」。

1. 打开授权页面，在「第 2 步」的表格里，那个档案的一行点 **重新授权**（不用先删除）。
2. 跟第 3 步一样登录、选角色、同意。
3. 回到 QQ 发「市场状态」，确认档案和建筑都变回 🟢。

- 想换一个服务角色：同样点「重新授权」，在 EVE 登录页选另一个角色。
- 第 1 步里加了权限、或者重新生成了 Secret Key（填回控制台以后）：都要重新授权一次。
- 改了 EVE 账号密码以后要不要重新授权待核实；如果「市场状态」变成「需要重新授权」，照上面做就行。

## 删除授权、撤销

- 授权页面里档案那一行点 **删除**，确认。插件会顺便请 EVE 撤销这次授权，用这个档案的建筑市场变成「需要授权」。
- 也可以在 EVE 的账号管理页里找到「第三方应用」之类的入口撤销（具体位置待核实）。在那边撤销以后，「市场状态」会在下一次刷新令牌时变成「🔴 需要重新授权」。

## 换电脑、备份

插件的文件在 Koishi 实例目录下的 `data/eve-market/` 里：

```
data/eve-market/
├── secret.key     加密刷新令牌用的密钥（第一次启动时自动生成）
└── cache/         数据和建筑订单的缓存（丢了会自动重新下载）
```

- 刷新令牌加密保存在数据库（例如 `data/koishi.db`）里，**解密要用 `secret.key`**。两样分开存放：只拿到数据库的人解不开令牌。
- **换电脑、重装时，把数据库和 `secret.key` 一起带过去**。只带了数据库、没带 `secret.key` 时，「市场状态」里档案显示「🟡 需要授权」，下面一行写着「保存授权用的密钥变了（换了机器或 secret.key 丢了），请重新授权」：要么把原来的 `secret.key` 放回去，再让插件重新启动（在控制台里把本插件停用再启用，或者重启 Koishi；只点「重载配置」、配置没有改动时插件不会重新启动），就自动恢复；要么重新授权一次（一分钟的事）。
- 备份时 `secret.key` 和数据库一起备份。不要把 `secret.key` 发给别人，也不要放进公开分享的网盘目录。
- 换了电脑以后，「你打开控制台用的地址」如果变了（例如隧道换了端口），开发者网站上的 Callback URL 和控制台里的「回调地址」两处都要改成新的，再重新授权。

## 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 授权页面显示「只接受本机访问」 | 不是在 Koishi 那台电脑上打开的；或者经反向代理、内网穿透打开的；或者地址栏里用的不是 `127.0.0.1`、`localhost` | 在那台电脑上（或者经 SSH 隧道）用 `http://127.0.0.1:端口` 或 `http://localhost:端口` 打开 |
| 授权页面显示「插件还没准备好」 | 插件还在启动，或者启动时出了错 | 等几秒刷新页面；一直这样的话，看一下 Koishi 的日志里本插件的报错 |
| 授权页面打不开（404 或连不上） | server 插件没启用，或者地址不对 | 从控制台本插件设置页最上面的「打开 EVE 授权页面」进入；「市场状态」里看有没有「需要 Koishi 的 server 插件」 |
| 授权页面「第 1 步」标红 | 控制台里的回调地址和你现在用的地址不一样 | 照抄页面上显示的那一行，改控制台和开发者网站两处 |
| EVE 登录页报回调地址不对（redirect_uri 之类） | 开发者网站上的 Callback URL 和控制台里的回调地址不完全一样 | 两处改成一模一样（注意端口、`127.0.0.1` 和 `localhost`、末尾的 `/`） |
| 登录后浏览器显示「无法访问此网站」 | 回调地址里的地址你的浏览器打不开，例如写的是 5140 端口，你用的是隧道的另一个端口；或者写成了 `https` | 回调地址改成「你打开控制台用的地址」加 `/eve-market/sso/callback`（`http` 开头） |
| 「授权链接已失效」：「这次授权的链接已经过期（10 分钟内有效）或者已经用过了。」 | 从点「授权」到登录完超过了 10 分钟，或者刷新、后退时又用了一次 | 回到授权页面重新点「授权」 |
| 「开始授权」页面写着「刚才的链接已经过期或用过了。」 | 授权页面打开太久（超过 30 分钟），或者按钮已经点过一次 | 点这一页上的「授权」按钮就行 |
| 「授权被取消」 | 在 EVE 登录页点了取消，或者没有同意权限 | 回到授权页面重新点「授权」，在 EVE 登录页点同意（**Authorize**）；一直这样的话，检查开发者网站上的应用是不是勾了第 1 步的三项权限 |
| 「授权码已经失效（超过有效期或用过了）」 | 登录完以后过了太久才回到页面，或者刷新了回调页面 | 回到授权页面重新点「授权」 |
| 「EVE 不认这个应用的 Client ID 或 Secret Key」 | 复制错了，或者 Secret Key 重新生成过 | 重新复制、填好、保存，再重新授权 |
| 「权限不够：缺少 …」 | 开发者网站上的应用没勾上这项权限 | 在开发者网站编辑应用，勾上缺少的权限并保存，再重新授权 |
| 授权成功，但建筑「没有权限（403）」 | 这个角色不能停靠，或者建筑没有对它开放市场 | 换能停靠的角色重新授权，或者请建筑管理者调整访问名单；然后发「市场状态 刷新」 |
| 按名字搜不到建筑 | 字数不到 3 个；或者这个角色看不到这个建筑；或者没勾 `esi-search.search_structures.v1`（页面上会提示） | 换个写法；确认角色能停靠；补勾权限后重新授权 |
| 搜索时提示「EVE 的搜索接口拒绝了请求」 | EVE 那边临时出错，或者搜索接口改了 | 改用第 4 步最后一段的办法，从游戏里的建筑链接找建筑 ID；并告诉开发者 |
| 群里查价显示「市场数据暂时不可用（ESI 授权或建筑访问权限异常）」 | 档案或建筑出了问题 | 管理员发「市场状态」，按上面的状态表处理 |
| 档案一直是「🟡 暂时刷新不了」 | 连不上 EVE 登录服务器（网络或代理问题） | 检查 Koishi 那台电脑能不能访问 `login.eveonline.com`；恢复后自动变回正常 |

## 安全说明

- Secret Key 和授权页面的口令只填在控制台里；控制台里它们显示为密码框。
- 授权页面只接受在 Koishi 所在电脑上直接打开：连接必须来自本机；带着反向代理、内网穿透加的转发标记（`X-Forwarded-For` 等）的一律拒绝（只看有没有，从不拿它的内容当成放行的理由）；地址栏里必须是 `127.0.0.1`、`localhost` 或者回调地址里的主机名，别的网站把自己的域名指到你的电脑上也打不开（防 DNS 重绑定）。
- 「授权」「删除」「搜索」都要带页面上一次性的令牌；别的网页发起的、浏览器预取的请求只显示确认页，什么都不做。
- 不是所有转发工具都会加转发标记：只要这台电脑上有反向代理、内网穿透或端口转发把 Koishi 的端口开放出去，就一定要设「授权页面的口令」。
- 页面、QQ 消息、「市场状态」和日志里都不显示 EVE 的令牌、授权码和 Secret Key。
- 不要把授权页面截图发到群里：上面虽然没有密钥，但有角色名和建筑 ID。

## 待核实的事项

下面这些是按目前的认识写的，还没有在 EVE 那边逐一确认。插件里它们都是写在 `src/constants.ts` 里的常量，确认后发补丁版本修改，你不用改任何配置。

- EVE SSO（v2）的地址：授权 `https://login.eveonline.com/v2/oauth/authorize`，换令牌和刷新 `https://login.eveonline.com/v2/oauth/token`（用 HTTP Basic 方式带上 Client ID 和 Secret Key），撤销 `https://login.eveonline.com/v2/oauth/revoke`。
- 令牌（JWT）里的签发者写法（`login.eveonline.com` 或 `https://login.eveonline.com`）、受众、权限字段 `scp` 是字符串还是数组、角色名和所属账号的字段名（`name`、`owner`）、角色 ID 的写法（`CHARACTER:EVE:<角色ID>`）。插件只解码、不验签（令牌是插件自己经 HTTPS 从 EVE 拿到的），所以不取 JWKS（`https://login.eveonline.com/oauth/jwks`）。
- 刷新时 EVE 会不会换一个新的刷新令牌：插件按「会换」处理，每次都保存最新的。
- 按名字找建筑的接口 `/characters/{角色ID}/search`（权限名 `esi-search.search_structures.v1` 已确认存在，搜索可用）。
- 开发者网站上「连接类型」的确切写法，Secret Key 以后还能不能再看。
- 改了 EVE 账号密码以后授权会不会失效；EVE 账号管理页里撤销第三方应用的入口位置。
- 游戏聊天里建筑链接复制出来的格式。
