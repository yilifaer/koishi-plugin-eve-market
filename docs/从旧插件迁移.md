# 从旧插件迁移

本插件取代以前用的下面 5 个旧插件：

| 旧插件 | 原来做什么 |
|---|---|
| evemarket2 | 查价（ojita 等）、造价、翻译、告示、简称 |
| evedatabase | 物品数据库（eveupdate） |
| eveonline-rq | 入侵（rq） |
| eveonline-influence-map | 势力图（omap、omap2） |
| eve-br | 战报自动截图 |

迁移以后：

- 查价这些功能**只由 QQ 官方机器人回答**，群友要先 @官方机器人 再输入命令。
- 原来的 LLBot 账号（OneBot）只做群管理和 Discord 转发，不再回答查价。
- 只有新的中文命令，旧的英文命令（ojita、rq、omap 等）不再有效。对照表在本文后面。

> 下文的「测试群」「联盟市场A」都是举例，换成你自己的。
> 整体的先后顺序（和 QQ机器人注册、EVE授权、测试步骤怎么穿插）见 [README 的「文档」一节](../README.md#文档)。
> 下文说「保存」，都是指点插件配置页右上角的勾号图标「重载配置」（鼠标移上去会显示名字），或者按 Ctrl+S。详见 [控制台配置.md](控制台配置.md) 的「怎么保存」。

## 先知道两件事

**1. 安装、升级、卸载插件，会让整个 Koishi 重启一次。**

实测是整个程序重启（日志也换了一个新文件），转发断了大约 20 秒。重启时 LLBot 和 dcqq-bridge 会断开再重连。这段时间里 Discord 和 QQ 之间的消息**不会补发**，会丢。所以每次都：

1. 挑群里没人说话的时候做；
2. 做完以后私聊 LLBot 发 `bridge.status`，确认转发恢复：回复里没有「QQ 未连接」「QQ 机器人离线」这类字样，和你平时看到的一样（拿不准的话，动手之前先发一次存个截图，做完再发一次对比）；
3. 在群里发一句话，看 Discord 那边收到没有。

**2. 在控制台里改插件的配置、启用、停用插件，只重载那一个插件。** 不影响转发，随时可以做。

所以下面的步骤里，**只有第 3 步（安装）要挑时间**；第 1 步备份用「停 Koishi」的做法时也要挑时间，用 `sqlite3` 在线备份就不用。其他都可以随时做。

## 迁移顺序

1. 备份。
2. **启用 adapter-qq 之前**，给要留在 LLBot 上的插件设过滤器（平台 等于 onebot）。
3. 挑群里没人说话的时候安装本插件，然后启用 adapter-qq。
4. 按 [测试步骤.md](测试步骤.md) 测试。
5. 正式版（0.1.0）测试通过后，**停用**（不是卸载）5 个旧插件。
6. 同时在群里发公告。
7. 出问题时回滚：把旧插件重新启用。
8. 旧插件都停用以后，再检查一遍其他插件的过滤器。

下面一步一步说。

## 第 1 步：备份

改配置、装插件之前，先备份这几个文件。

**这一步要在运行 Koishi 的那台电脑上做。** 你经 SSH 隧道在浏览器里打开控制台时，Koishi 和它的文件在隧道另一头的那台电脑上，不在你眼前这台。要坐到那台电脑前（或者用远程桌面登录它）操作。

文件都在 **Koishi 实例目录**里（就是 `koishi.yml` 所在的文件夹）。Koishi Desktop 可以从它的实例管理里打开这个文件夹（按钮的名字以实际界面为准）。

| 文件 | 是什么 |
|---|---|
| `koishi.yml` | 所有插件的配置 |
| `data/koishi.db` | 数据库（用的是 SQLite 时的默认文件名） |
| `data/eve-market/secret.key` | 做过 EVE 授权以后才有，见 [EVE授权.md](EVE授权.md) |

有两种做法，任选一种。

**做法一：不停 Koishi（那台电脑上有 `sqlite3` 命令时，Mac 一般自带）**

1. 在 Koishi 实例目录里打开终端（Mac：在访达里右键这个文件夹，选「新建位于文件夹位置的终端窗口」）。
2. 数据库用 `sqlite3` 在线备份（Koishi 照常运行，不会断转发）：

   ```
   sqlite3 data/koishi.db ".backup data/koishi.db.bak-20261013"
   ```

3. 检查备份是好的，回一个 `ok` 就对了：

   ```
   sqlite3 data/koishi.db.bak-20261013 "PRAGMA integrity_check"
   ```

4. `koishi.yml` 和 `data/eve-market/secret.key`（有的话）直接复制一份，名字后面加上日期。

**做法二：停一下 Koishi 再复制**

1. 挑群里没人说话的时候，**停止 Koishi**：在那台电脑上打开 Koishi Desktop，点这个实例的「停止」按钮（以实际界面为准）。停止以后浏览器里的控制台会连不上，这是正常的。数据库在 Koishi 运行时一直在写，停下来再复制最稳妥。
2. 把上面每个文件**复制**一份，放在原来的文件旁边，名字后面加上日期，例如 `koishi.yml.bak-20261009`、`koishi.db.bak-20261009`。不要改原来的文件。
3. **启动 Koishi**：在 Koishi Desktop 里点「启动」。等控制台能打开以后，照上面的方法检查转发（停止、启动也会断一下转发）。

- 备份文件里有密钥，不要发给别人，也不要放进公开分享的网盘目录。

## 第 2 步：给留在 LLBot 上的插件设过滤器

**一定要在启用 adapter-qq 之前做。**

为什么：

- 官方机器人收到的 @ 消息，Koishi 会交给**所有**插件处理。不设过滤器的话，旧插件和别的插件的命令也会经官方机器人回答，占用官方机器人的回复次数。
- 旧的 eve-br 不分平台，看到战报链接就截图。不设过滤器的话，同一个链接会被新旧插件各截一次。

**要设过滤器的插件**（只在 LLBot 上用的）：

- 5 个旧插件：evemarket2、evedatabase、eveonline-rq、eveonline-influence-map、eve-br；
- 其他只给 LLBot 用的命令类插件，例如复读、群管理工具。

**同时在 LLBot 和 Discord 上用的插件**（例如在 QQ 群和 Discord 里都能用的命令）：过滤器不要设成只有 onebot，否则 Discord 那边也不能用了。改成「平台」「属于」，值填 `onebot, discord`（见下面「怎么设」的第 5 点）。

**不要设过滤器的插件**：

- **dcqq-bridge**：它要同时处理 Discord 和 QQ 的消息，设成只在 onebot 上会让转发停掉（它的过滤器另有设法，见下面「转发插件的过滤器」）；
- help（帮助插件）：「帮助」已经由本插件接管，测过；
- 各个适配器（adapter-onebot、adapter-qq、Discord 的适配器）、数据库、控制台、沙盒、puppeteer 这类基础插件；
- 本插件（eve-market）：它自己已经只在 QQ 官方机器人上回复。

**怎么设**（每个插件都做一遍）：

1. 打开 Koishi 控制台 → 「插件配置」，在左边点开这个插件。
2. 在右边的设置页里往下找到「**过滤器设置**」这一节（在插件说明的下面、这个插件自己的配置项的上面）。
3. 点「**添加条件**」。会出现一行：两个下拉菜单和一个输入框。
4. 第一个下拉菜单选「**平台**」，第二个选「**等于**」，输入框里填 `onebot`。意思是「只在 onebot 平台（LLBot）上生效」。
5. 同时在 Discord 上用的插件：第二个下拉菜单改选「**属于**」，输入框里填 `onebot, discord`（中间是英文逗号）。
6. 保存：点右上角的勾号「重载配置」，或者按 Ctrl+S。插件停用着的话，点软盘图标「保存配置」。
7. 填错了：点这一行最左边的删除按钮（垃圾桶图标），删掉重新加。

**检查**：照你们平时的用法，在群里发一个旧命令（例如 `ojita 乌鸦级`），LLBot 应该照旧回复。过滤器只是不让它们在官方机器人上生效，LLBot 上一切照旧。

### 转发插件的过滤器

Discord 和 QQ 之间的转发插件（例如 dcqq-bridge）和官方机器人在同一个 Koishi 里时，官方机器人在群里发的回复也会被它当成普通消息转发出去。给转发插件加一个过滤器，让它不处理官方机器人自己的消息：

1. 打开这个转发插件的设置页，找到「过滤器设置」，点「添加条件」。
2. 第一个下拉菜单选「**用户 ID**」，第二个选「**不等于**」，输入框里填官方机器人的号（adapter-qq 配置里的 QQ 机器人 ID，也就是机器人自己的用户 ID）。菜单名称以实际界面为准。
3. 保存（方法同上）。设好以后，官方机器人的回复不再被转发。

## 第 3 步：安装本插件，启用 adapter-qq

**挑群里没人说话的时候做。**

1. 打开控制台的「插件市场」，搜索 `koishi-plugin-eve-market`，**确认作者是 yilifaer**，点安装。
   - 新版本刚发布时，插件市场一般要过几个小时才显示（测试版能不能在市场里选到待实测）。
   - 升级已装的插件前，先在「依赖管理」页面右上角点一下「刷新」，否则版本列表可能还显示旧版本（用 npmmirror 这类镜像时尤其常见）。
   - 搜不到、或者没有你要的版本：过几个小时再搜。还是没有，就告诉开发者，**不要从别的地方下载安装**。
2. 安装完 Koishi 会整个重启一次（转发断大约 20 秒）。等控制台恢复以后：
   - 私聊 LLBot 发 `bridge.status`，确认转发恢复；
   - 在群里发一句话，看 Discord 那边收到没有。
3. 装好以后，「插件配置」里**还没有** eve-market（`koishi.yml` 里也没有它）。要自己加进去：
   1. 在「插件配置」页面点右上角的插头图标「**添加插件**」（鼠标移上去会显示名字）。
   2. 搜 `eve-market`，选它。左边的插件列表里会多出一个 eve-market。
   3. 点开它，看一眼「市场」表格（预置了 Jita 和另外四个 NPC 交易中心），然后点右上角的三角图标「**启用插件**」。
   - 安装时控制台可能会跳到一个新条目的页面，但 Koishi 重启以后这个条目就没了，所以照上面重新添加一次。
4. 按 [QQ机器人注册.md](QQ机器人注册.md) 第 6–8 步：填好 adapter-qq、启用、确认上线、发「本群ID」填授权群和管理员。
   - QQ 机器人还没在开放平台创建的，先做注册的第 1–5 步。
   - 想先在控制台的沙盒里试一遍，先做 [测试步骤.md](测试步骤.md) 的 A 部分，再回来做这一点。

到这一步，新旧插件同时在用：旧命令由 LLBot 回答，新命令由官方机器人回答，互不干扰。

## 第 4 步：测试

按 [测试步骤.md](测试步骤.md) 的 B 部分，在测试群里测。旧的 eve-br 还开着时，在群里发战报链接，LLBot 也会截一张图，属正常。

旧插件还开着时，日志里偶尔会有一条 `[W] command` 警告，第一行是官方机器人的一条回复（后面带着 `<markdown content=…>`）。这是 LLBot 也收到了官方机器人发在群里的消息，旧插件把它当成命令执行、出了错，不是本插件的问题，不影响使用。停用旧插件以后就没有了。

测试版（0.0.x）升级到新版本时，同样挑没人说话的时候，做完照第 3 步第 2 点检查转发。

升级以后重启完，还要看一眼 puppeteer（走势图、战报截图要用）：打开控制台里 eve-market 的页面，看「可选服务：puppeteer」是不是「已加载」。不是的话（Mac 内存紧张时，Chrome 启动可能超时，日志里有 `Timed out after 30000 ms while waiting for the WS endpoint URL`），在控制台把 puppeteer 插件停用再启用就好。

## 第 5 步：停用旧插件

**等正式版（0.1.0）测试通过以后再做。**

1. 打开控制台「插件配置」，依次点开 evemarket2、evedatabase、eveonline-rq、eveonline-influence-map、eve-br。
2. 每个都点右上角的方块图标「**停用插件**」（鼠标移上去会显示这个名字）。每个插件的停用都是单独、立即生效的，不会让整个 Koishi 重启。
3. **只停用，不卸载**：卸载又会让整个 Koishi 重启一次；留着也方便出问题时退回去。旧插件的配置和数据都还在。


## 第 6 步：发群公告

停用旧插件的同时，在每个群里发一次公告。模板在本文最后。

## 第 7 步：出问题时回滚

| 情况 | 怎么做 |
|---|---|
| 新插件有问题，想先用回旧的 | 把 5 个旧插件重新启用：点开每一个，点右上角的三角图标「启用插件」（它们的过滤器还在，只在 LLBot 上生效）。必要时把本插件也停用 |
| 官方机器人有问题（不上线、乱回复） | 停用 adapter-qq。旧插件照常在 LLBot 上用 |
| 配置改乱了，自己改不回来 | 用第 1 步的备份恢复，见下面 |

前两种都不会删掉任何数据，随时可以再切回来。

**用备份恢复**（在运行 Koishi 的那台电脑上做，挑群里没人说话的时候；也会断一下转发）：

1. 停止 Koishi（Koishi Desktop 里点「停止」）。
2. 在实例目录里，把现在的 `koishi.yml` 改名成 `koishi.yml.坏-20261009`（日期写今天的）。先留着，万一要找回什么。
3. 把备份 `koishi.yml.bak-20261009` **复制**一份，把复制出来的那份改名成 `koishi.yml`。
4. 数据库也要恢复时，在 `data` 文件夹里对 `koishi.db` 做同样的事：现在的改名成 `koishi.db.坏-日期`，复制备份、改名成 `koishi.db`。
5. 启动 Koishi（Koishi Desktop 里点「启动」），等控制台能打开。
6. 私聊 LLBot 发 `bridge.status`，确认转发恢复；在群里发一句话，看 Discord 那边收到没有。

注意：用旧的 `koishi.db` 恢复以后，EVE 授权多半要重新做一次：备份之后做过的授权不在旧数据库里，旧数据库里的授权也可能已经失效。管理员发「市场状态」，档案显示「需要授权」或「需要重新授权」时，按 [EVE授权.md](EVE授权.md) 的「重新授权」做。只恢复 `koishi.yml` 不影响授权。

## 第 8 步：最后检查过滤器

旧插件都停用以后，再看一遍其他插件的过滤器：

- 只给 LLBot 用的命令类插件：过滤器还是「平台 等于 onebot」；同时在 Discord 上用的：「平台 属于 onebot, discord」；
- dcqq-bridge：只有上面「转发插件的过滤器」那一条（用户 ID 不等于官方机器人的号）；help、适配器、本插件：没有过滤器。

## 旧命令对照表

每个旧命令都有去处。新命令在群里都要先 @官方机器人。

| 旧命令 | 新的 |
|---|---|
| `ojita`、`jita` | `查价`（只有欧服） |
| `ocol`、`col` | `搜索`（一个名字列出相关物品，并带价格）；粘贴清单用 `批量查价` |
| `rq` | `入侵`；`rq -g`（国服）不再支持 |
| `omap` / `omap2` | `势力图` / `联盟势力图`；`map`（国服）不再支持 |
| eve-br 自动截图 | @官方机器人 直接发战报链接，或者 `战报 <链接>`。不 @ 机器人的消息不会再自动截图 |
| `dt` | `服务器状态` |
| `trans` | `翻译`（也可以写 `中英对照`） |
| `cost` | `制造`（0.0.4 起；`制造比价` 比较几个地点，`反应` 算反应） |
| `cont`、`scont`、`tage` | `批量查价`。折扣每次写在命令后面（`批量查价 -5%`），不再按人记 |
| `add`、`eveupdate` | 不再需要：物品数据每周自动更新，新物品也能查 |
| `name`、`dname`、`简称` | 控制台「物品别名」；黑话表里的叫法自动能用 |
| `ad`、`showad`、`delad` | 控制台「查价告示」 |
| `donate`、`赞助` | 不保留 |

## 旧插件的数据

- 旧插件在数据库里的表（物品库、价格调整、告示等）**不再需要**，留着不管就行，不用删。
- 旧插件里自定义的简称**不会自动搬过来**。常用的几个，在控制台本插件的「物品别名」里重新加一下；黑话表里已经有的不用加。
- 旧插件里的告示，在控制台「查价告示」里重新写（最多显示 2 条）。

## 群公告模板

把「官方机器人」换成你的机器人的名字。

```
【查价机器人换新了】
以后查价请先 @官方机器人 再输入命令。@ 要从输入框的 @ 列表里选它，手打名字不算。

常用：
@官方机器人 查价 乌鸦级
@官方机器人 批量查价（换行后粘贴清单或装配）
@官方机器人 走势 乌鸦级
@官方机器人 入侵 / 势力图 / 服务器状态
战报：@官方机器人 直接发 BR 链接

旧命令对照：ojita → 查价，ocol → 搜索，cont → 批量查价，rq → 入侵，omap → 势力图，omap2 → 联盟势力图，dt → 服务器状态，trans → 翻译。
造价（cost）要等下一个版本的「制造」。

发「@官方机器人 帮助」看全部用法。
```

配好「/」指令面板以后（见 [QQ机器人注册.md](QQ机器人注册.md) 第 11 步），可以在第二行后面加一句：「也可以点输入框里的「/」选命令。」
